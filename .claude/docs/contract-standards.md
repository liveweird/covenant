### The contract standards (domain reference)

The formats Covenant stores, validates and diffs — an offline snapshot of the essentials, so a contract feature is designed from here instead of from a browser tab. Each section names the upstream source it summarizes (snapshot 2026-09-05); re-check upstream and update this file when adding a validation rule. The document itself is always stored **verbatim** (raw YAML or JSON); everything below is what Covenant READS out of it (the type gate, metadata extraction, validators) — never what it rewrites.

**Type gate (HARD — `contracts/checks/DocumentParser.kt`).** A document is OPENAPI iff its root has `openapi: "3.x.y"` (a `swagger: "2.0"` root is refused as `UNSUPPORTED_SPEC_VERSION` — Covenant does not store Swagger 2.0; convert upstream), ASYNCAPI iff `asyncapi: "2.6.0" | "3.0.0" | "3.1.0"`, ODCS iff `kind: DataContract` AND `apiVersion: v3.x.y`. Anything else is `TYPE_MISMATCH` against the contract's declared type — a `400` on every store path.

**OpenAPI 3.0 / 3.1** (<https://spec.openapis.org/oas/v3.1.0>, <https://spec.openapis.org/oas/v3.0.3>). Root: `openapi` (the version string), `info` (`title` and `version` REQUIRED; `description`, `summary` 3.1-only), `servers[]`, `paths` (REQUIRED in 3.0; in 3.1 at least one of `paths`/`components`/`webhooks`), `components` (`schemas`, `responses`, `parameters`, `requestBodies`, `headers`, `securitySchemes`, `links`, `callbacks`, `pathItems` 3.1), `security`, `tags`, `externalDocs`. Path item → operations (`get`/`put`/`post`/…), each with `operationId` (unique — a lint rule), `parameters` (`in: path|query|header|cookie`), `requestBody`, `responses` (keyed by status or `default`). Schema objects: 3.0 uses an extended JSON-Schema-draft-05-ish subset (`nullable: true`, boolean `exclusiveMinimum`, no `type` arrays, `example`); **3.1 is a full JSON Schema 2020-12 superset** (`type: ["string","null"]`, numeric `exclusiveMinimum`, `examples[]`, `$schema`/`jsonSchemaDialect`, `const`, `unevaluatedProperties`). `$ref` is a JSON pointer into the same document (`#/components/schemas/X`) or another document — Covenant treats an external `$ref` as a finding (`EXTERNAL_REF_UNRESOLVED`), never fetches it. Metadata Covenant extracts: `spec_version = openapi`, `doc_title = info.title`, `doc_description = info.description`; `info.version` is compared to the SemVer being stored (INFO `VERSION_MISMATCH` when they differ). Validators: JVM `swagger-parser-v3` (`OpenAPIV3Parser().readContents(text, null, ParseOptions{resolve=false, validateInternalRefs=true})` — its `messages` are SEMANTIC findings), checker Spectral `spectral:oas` ruleset (LINT + `oas3-schema` SCHEMA). Breaking changes (`contracts/checks/OpenApiBreaking.kt` over `openapi-diff-core`, its verdicts walked into one `BREAKING` fact per element — `REMOVED_OPERATION`, `REMOVED_PARAMETER`, `NEW_REQUIRED_PARAMETER`, `CHANGED_PARAMETER`, `CHANGED_REQUEST_BODY`, `REMOVED_RESPONSE`, `CHANGED_RESPONSE`, `CHANGED_SECURITY`, else `INCOMPATIBLE_OPERATION`): removed paths/operations/parameters/response codes, a new required parameter or request property, a narrowed type or enum, a removed REQUIRED response property (openapi-diff deems an optional one's removal compatible), a changed security requirement — MAJOR; additive optional changes — MINOR; description/example changes — PATCH. 3.1 documents are compared through the 3.0 model (the root relabelled for the comparison only — swagger-parser's generic 3.1 `JsonSchema` is opaque to the differ), so 3.1-only constructs are invisible to the comparison.

**AsyncAPI 2.6 vs 3.x** (<https://www.asyncapi.com/docs/reference/specification/v2.6.0>, <https://www.asyncapi.com/docs/reference/specification/v3.0.0>). Common root: `asyncapi` (version), `info` (`title`, `version` REQUIRED), `servers` (keyed; `host`/`protocol` in 3.x, `url` in 2.x), `defaultContentType`, `components` (`messages`, `schemas`, `channels` 3.x, `operations` 3.x, `securitySchemes`, `parameters`, …). **2.6**: `channels` keyed by the channel ADDRESS, each holding `publish`/`subscribe` operations with a `message` (or `oneOf` messages); a message has `payload`, `headers`, `contentType`, `schemaFormat`, `name`, `title`. **3.x**: `channels` keyed by an arbitrary id with `address` inside and `messages` (keyed) — and a separate root `operations` map, each with `action: send | receive`, a `channel` `$ref`, optional `messages[]` `$ref`s and `reply`; `info.tags`/`externalDocs`, `servers` gain `host`/`pathname`. Payload schema formats (`schemaFormat` on a message or a `payload` object with `schema`+`schemaFormat` in 3.x): the default is the AsyncAPI Schema Object (a JSON Schema draft-07 superset); explicit values include `application/schema+json;version=draft-07`, `application/vnd.aai.asyncapi;version=3.0.0`, `application/vnd.apache.avro;version=1.9.0` (Avro), `application/vnd.oai.openapi;version=3.0.0`. **Covenant accepts JSON Schema 2020-12 (default) and Avro** for payloads: a non-Avro payload is meta-validated against the 2020-12 meta-schema (`PAYLOAD_SCHEMA_INVALID`), an Avro payload is parsed by Apache Avro (`AVRO_INVALID`); Protobuf and other formats are reported as INFO `PAYLOAD_FORMAT_UNCHECKED` (milestone 3). Recommended (documented, not enforced): **CloudEvents** (<https://cloudevents.io>, spec 1.0) as the message ENVELOPE — `id`, `source`, `specversion`, `type` + optional `datacontenttype`, `dataschema`, `subject`, `time`, `data` — with the domain payload under `data`. Metadata: `spec_version = asyncapi`, `doc_title = info.title`, `doc_description = info.description`, `info.version` vs the stored SemVer. Validators: JVM networknt against the vendored schema for the declared version (`schemas/asyncapi/<v>.json`, SCHEMA `ASYNCAPI_SCHEMA`), then the payload walk (`components.messages.*.payload`, 3.x `channels.*.messages.*.payload`, 2.x `channels.*.publish|subscribe.message.payload`); checker `@asyncapi/parser` (SEMANTIC — its own ruleset: `asyncapi-schema`, channel/operation/server/security consistency) + Spectral `spectral:asyncapi` (LINT). Breaking changes (the checker's `@asyncapi/diff` pass, see `.claude/docs/checker.md` — facts `breaking-add|remove|edit` at the change's pointer): removed channels/operations/messages, a payload field removed or made required, a narrowed type, a changed `address`/server protocol — MAJOR; additive — MINOR; the differ's `/info/version` verdict is overridden (every new version edits it).

**ODCS — Open Data Contract Standard 3.x** (<https://bitol-io.github.io/open-data-contract-standard/latest/>, schemas in `bitol-io/open-data-contract-standard/schema/`). Root (REQUIRED in bold): **`apiVersion`** (`v3.0.0` … `v3.1.0`), **`kind: DataContract`**, **`id`** (a UUID or any stable identifier), **`version`** (the contract's own SemVer), **`status`** (`proposed | draft | active | deprecated | retired` — the same vocabulary as Covenant's lifecycle, deliberately; Covenant's lifecycle is the row's, the document's `status` is INFO-compared to it), `name`, `domain`, `dataProduct`, `tenant`, `tags[]`, `description` (`purpose`, `limitations`, `usage`, `authoritativeDefinitions[]`, `customProperties[]`), **`schema[]`** (the datasets: each with `name`, `physicalName`, `physicalType` (`table`/`view`/`topic`/`file`/`object`…), `logicalType` (`object`), `description`, `businessName`, `dataGranularityDescription`, `tags`, `authoritativeDefinitions`, `quality[]`, `customProperties[]`, and `properties[]` — the columns: `name`, `logicalType` (`string|number|integer|boolean|date|array|object`), `logicalTypeOptions` (`format`, `minLength`, `pattern`, `precision`, …), `physicalType`, `physicalName`, `description`, `required`, `unique`, `primaryKey` + `primaryKeyPosition`, `partitioned` + `partitionKeyPosition`, `classification`, `encryptedName`, `transformSourceObjects`/`transformLogic`/`transformDescription`, `examples[]`, `criticalDataElement`, `quality[]`, `items` (arrays), `properties[]` (nested objects)), `servers[]` (`server`, `type` — `bigquery|snowflake|postgres|kafka|s3|…` — plus type-specific keys like `host`/`port`/`database`/`schema`, `environment`, `roles[]`), `support[]` (`channel`, `url`, `tool`, `scope`, `description`), `price` (`priceAmount`, `priceCurrency`, `priceUnit`), `team[]` (`username`, `role`, `dateIn`/`dateOut`, `replacedByUsername`), `roles[]` (`role`, `access`, `firstLevelApprovers`, `secondLevelApprovers`), `slaDefaultElement`, `slaProperties[]` (`property`, `value`, `valueExt`, `unit`, `element`, `driver`), `authoritativeDefinitions[]`, `customProperties[]` (`property` + `value`), `contractCreatedTs`. Quality rules (`quality[]` at schema or property level): `type: library | text | sql | custom` with `rule`/`query`/`engine`/`implementation`, `mustBe*` thresholds, `dimension` (accuracy/completeness/…), `severity`, `businessImpact`, `scheduler`/`schedule`. Metadata Covenant extracts: `spec_version = apiVersion`, `doc_title = name ?: id`, `doc_description = description.purpose ?: description.usage`; `version` vs the stored SemVer (INFO on mismatch), `status` vs the lifecycle (INFO). Validators: JVM networknt against `schemas/odcs/odcs-json-schema-v<apiVersion>.json` (SCHEMA `ODCS_SCHEMA`); the checker runs nothing for ODCS — a standing decision, revisited only if a Spectral ODCS ruleset earns its keep. Breaking changes (`contracts/checks/OdcsBreaking.kt`, hand-written — no library covers ODCS; datasets, properties and servers matched by NAME, pointers into the candidate): a removed dataset or property (`REMOVED_DATASET`/`REMOVED_PROPERTY`, nested properties included), a property newly `required` (`PROPERTY_NOW_REQUIRED`), a changed `logicalType`/`physicalType` (`CHANGED_LOGICAL_TYPE`/`CHANGED_PHYSICAL_TYPE`), a removed server (`REMOVED_SERVER`) — MAJOR; a new optional property, a new quality rule, SLA/support/team edits — MINOR/PATCH (not flagged).

**JSON Schema 2020-12** (<https://json-schema.org/draft/2020-12/json-schema-core>, `…/json-schema-validation`). The default payload schema language. Core keywords: `$schema`, `$id`, `$ref`, `$defs`, `$anchor`, `$dynamicRef`/`$dynamicAnchor`, `$comment`; applicators `allOf`/`anyOf`/`oneOf`/`not`, `if`/`then`/`else`, `properties`/`patternProperties`/`additionalProperties`/`unevaluatedProperties`, `items`/`prefixItems`/`contains`/`unevaluatedItems`, `dependentSchemas`/`dependentRequired`; validation: `type` (a string or an array), `enum`, `const`, numeric `minimum`/`maximum`/`exclusiveMinimum`/`exclusiveMaximum`/`multipleOf`, string `minLength`/`maxLength`/`pattern`/`format` (annotation by default, assertion only with the format-assertion vocabulary), array `minItems`/`maxItems`/`uniqueItems`/`minContains`/`maxContains`, object `required`/`minProperties`/`maxProperties`/`propertyNames`; annotations `title`/`description`/`default`/`examples`/`deprecated`/`readOnly`/`writeOnly`/`contentMediaType`/`contentEncoding`. Differences from draft-07 (what AsyncAPI 2.x's default schema object and the AsyncAPI meta-schemas themselves use): `definitions` → `$defs`, `items` (array form) → `prefixItems`, `dependencies` → `dependentSchemas`/`dependentRequired`, `$ref` may sit beside other keywords. Meta-validation (is this document a valid SCHEMA?) is what Covenant does for payloads: networknt with `SpecVersion.VersionFlag.V202012`, no remote loaders.

**Apache Avro schemas** (<https://avro.apache.org/docs/1.12.0/specification/>). JSON documents: primitive types `null|boolean|int|long|float|double|bytes|string`; complex `record` (`name`, `namespace`, `doc`, `aliases`, `fields[]` with `name`, `type`, `doc`, `default`, `order`, `aliases`), `enum` (`symbols[]`, `default`), `array` (`items`), `map` (`values`), `union` (a JSON array of types — `["null","string"]` is the nullable idiom; a field default must match the FIRST branch), `fixed` (`size`); logical types via `logicalType` (`decimal` with `precision`/`scale`, `uuid`, `date`, `time-millis/micros`, `timestamp-millis/micros`, `local-timestamp-*`, `duration`). Names are `[A-Za-z_][A-Za-z0-9_]*`, full names `namespace.name`, unique within a schema. Covenant parses with `org.apache.avro.Schema.Parser().parse(json)` (`AVRO_INVALID` on failure). Evolution (NOT yet wired — an Avro payload inside an AsyncAPI document is compared structurally by the checker's `@asyncapi/diff` pass today; a dedicated Apache Avro `SchemaCompatibility` pass is a later add): a reader schema is compatible with a writer's when added fields have defaults, removed fields had defaults, types match or promote (`int→long→float→double`, `string↔bytes`), enum symbols are a superset for readers, union branches are matched — anything else is a breaking change.

**SemVer 2.0.0 and Covenant's version rules** (<https://semver.org/spec/v2.0.0.html>). `MAJOR.MINOR.PATCH[-prerelease][+build]`: numeric identifiers without leading zeros; prerelease identifiers dot-separated (`1.0.0-alpha.1`), precedence by numeric-then-lexical comparison of each identifier and a prerelease sorting BELOW its release; build metadata (`+20130313144700`) ignored in precedence. Covenant (`contracts/SemVer.kt`): the string is stored verbatim and must parse; versions are unique per contract (case-sensitive string equality); a NEW version must be strictly greater than the highest existing one (full precedence, prereleases included), so `1.2.0-rc.1` may follow `1.1.9` and `1.2.0` may follow `1.2.0-rc.1`, but nothing may follow `2.0.0` below it; the parsed `major/minor/patch/prerelease` columns give SQL ordering, the Kotlin comparator decides the rule. Lifecycle (`contracts/Lifecycle.kt`): `DRAFT → PROPOSED → ACTIVE → DEPRECATED → RETIRED`, plus `PROPOSED → DRAFT`; content editable only in DRAFT/PROPOSED; delete only DRAFT; several ACTIVE versions may coexist (that is what DEPRECATED is for). The bump rule (`contracts/checks/BreakingChanges.kt`): the **baseline** is the contract's highest ACTIVE version strictly below the candidate (`ContractVersionService.baselineFor` — so a recheck of an older version compares against ITS predecessor, a draft below the ACTIVE one compares against nothing, and a contract with no ACTIVE version is never compared); the engines report the FACTS as `BREAKING` findings, and `settle` decides: with the MAJOR bump they are INFO (the change log of a deliberate break), without it they stay WARN and ONE soft `ERROR` `BREAKING_WITHOUT_MAJOR_BUMP` blocks the strict save — waivable like every soft finding, and recorded as such. The live check joins in when the SPA names the contract (`DocumentCheckRequest.contractId`; the report's `baselineVersion` says what was compared); import predicts and stores with the same baseline.

**The compatibility report** (`GET …/{vid}/compatibility?against={otherVid}`, `contracts/checks/Compatibility.kt` + `ChecksService.compatibility`) answers the two-way question for an ARBITRARY pair, not just the fixed ACTIVE-baseline-vs-candidate the store path checks — a pure read, never stored, never audited, like `GET …/model`. With `from` the older/reference version and `to` the newer/candidate (`vid` is always `to`; `against` — omitted, the ACTIVE baseline below `vid` via `baselineFor`, else any version of the same contract, `against == vid` legal) it runs the SAME raw facts (`BreakingChanges.facts` / the checker's `@asyncapi/diff` pass) in BOTH directions, unsettled (no MAJOR-bump severity flip — that sentence is the SPA's): **backward compatible** — `from`'s consumers still work against `to` (comparing old=`from` → new=`to` yields no facts); **forward compatible** — `to`'s consumers already worked against `from` (old=`to` → new=`from` yields no facts). The two flags name a `CompatibilityVerdict`: `FULL` (both), `BACKWARD` (backward only), `FORWARD` (forward only), `NONE` (neither), `UNKNOWN` (a direction could not be computed — no ACTIVE predecessor, an unparseable side, a differ skip, the checker down for AsyncAPI). Beside it, `VersionBump` names the SemVer step from `from` to `to` — `MAJOR | MINOR | PATCH | PRERELEASE | NONE | DOWNGRADE` (the highest differing column wins; `DOWNGRADE` whenever `to` is actually the older side) — the "why" sentence: a MINOR/PATCH bump PROMISES backward compatibility, MAJOR permits a break.

**The render model (milestone 4, `contracts/render/`).** `GET …/{vid}/model` answers what the READER shows: a normalized, `$ref`-resolved, type-specific view computed per request from the Jackson tree with a hand-written pointer resolver — never swagger-parser's `resolve=true` (it routes external `$ref`s through file/HTTP I/O and its 3.1 model is an opaque `JsonSchema`). The shared primitive is `SchemaNode`: `type` normalized to a list minus `"null"` (→ `nullable`; OpenAPI 3.0's `nullable: true` too), `object`/`array` inferred from keywords, 3.0's boolean `exclusiveMinimum` folded into a constraint carrying the bound, `example` + `examples` unified, tuple `items: [...]` and 2020-12 `prefixItems` both as `tupleItems`, every non-string JSON value stringified compactly (no `{}`-typed spec fields); `$ref` chains followed in-document up to 8 hops with 3.1 sibling keywords overlaid, and the CYCLE RULE: a ref re-entering a schema on the CURRENT expansion stack (the node's own pointer included) is a `CIRCULAR` marker while two siblings referencing one schema both expand; an external or dangling ref is `UNRESOLVED`. A `RenderBudget` (depth 32, 20 000 nodes) bounds hostile documents — past it a `TRUNCATED` marker sits at the cut and the response says `truncated`. Avro payloads map through `AvroSchemaMapper` (record → object with fields required unless nullable-union or defaulted, enum → string + symbols, map → additionalProperties, unions → anyOf or a nullable single branch, fixed/logicalType → format, a named back-reference → `CIRCULAR`); unknown payload formats (protobuf) stay `raw` text. AsyncAPI 2.x is unified onto the 3.x vocabulary (`publish` → `receive`, `subscribe` → `send`, `legacyAction` kept, channel key = address); every message payload renders ONCE (component messages by key, inline ones as `<channel>/<key>`) and channels/operations point at those keys. A stored document that no longer parses or fails the type gate answers `200` with `error` set. The wire encoding omits absent optionals (`ContractRenderer.json`: no explicit nulls) — the spec declares them optional, and every list is always present. Tests: `JsonPointersTest`, `SchemaWalkerTest`, `AvroSchemaMapperTest`, the three `*RendererTest`s over `RenderFixtures`, `ContractRendererTest`, the `ContractVersionTest` route case.

**Finding vocabulary (shared by the JVM and the checker).** `severity ∈ {ERROR, WARN, INFO}`, `source ∈ {SYNTAX, SCHEMA, SEMANTIC, LINT, BREAKING, CONFORMANCE, SYSTEM, INFERENCE}`, `code` (a stable machine id — the JVM's own SCREAMING_SNAKE codes, Spectral's kebab rule ids, the parser's codes), `message`, optional `path` (a JSON pointer, `/paths/~1pets/get`), `line`/`column` (1-based). HARD = `source == SYNTAX`; a SOFT `ERROR` blocks a strict save; `WARN`/`INFO` never block; `SYSTEM` carries operational notes (`CHECKER_UNAVAILABLE`, `FINDINGS_TRUNCATED` at the 500-finding cap); `CONFORMANCE` is the try-it feature's voice (below) — a live observation, never a document defect, never stored; `INFERENCE` is the inference engine's voice (below) — a heuristic applied while building a draft, never stored either.

**Live conformance (milestone 3c, `contracts/tryit/`).** The try-it feature reaches a real target through an admin-curated Environment and measures what comes back against the document's OWN schemas — `source = CONFORMANCE`, computed per call and never stored on the version. `TryCatalog.kt` reads what a document offers to try, pure over the parsed tree: OpenAPI operations (method + path template, path-level and operation parameters merged — the operation wins on name+location, path parameters always required — the request body's media types, the response keys, the header-shaped security schemes), AsyncAPI channels (2.x: the channel key is the address, `publish`/`subscribe` are the verbs; 3.x: `address` + the verbs of the operations pointing at the channel; messages with their `contentType`/`schemaFormat` and the payload pointer, `$ref`'d messages followed, `oneOf` alternatives listed), ODCS datasets (`schema[]` entries with `physicalName`/`physicalType` and the flat `properties[]`). `Conformance.kt` answers where a validation schema comes from: the WHOLE document is served to an offline networknt registry under the synthetic IRI `urn:covenant:try:document` (a map resource — nothing fetched), so a sub-schema is addressed by its JSON pointer and its `#/components/...` refs resolve in-document; OpenAPI 3.0 documents validate through networknt's `OpenApi30` dialect (`nullable`, boolean `exclusiveMinimum`), 3.1 through `OpenApi31` (type arrays), AsyncAPI payloads through 2020-12 (the checks' default) and Avro payloads through Apache Avro's JSON decoder (`GenericDatumReader` + `jsonDecoder`); Protobuf and other formats are an INFO `PAYLOAD_NOT_VALIDATED`. The Kafka leg measures a payload BEFORE publishing it (`PAYLOAD_SCHEMA_MISMATCH` / `PAYLOAD_NOT_JSON` ERRORs under `/payload/...` — the record still goes out; an Avro payload is validated through Avro's JSON decoder and sent as its JSON encoding with the INFO `PAYLOAD_SENT_AS_JSON`) and every record of a tail read (paths `/messages/{i}/payload/...`; a tombstone is a WARN, a binary or 64 KiB-truncated payload an INFO). The HTTP leg picks the response by exact status, then the `NXX` range, then `default`, and the media type by exact match, then `+json` → `application/json`; `STATUS_UNDECLARED` / `RESPONSE_SCHEMA_MISMATCH` / `RESPONSE_NOT_JSON` are ERRORs (paths under `/body/...`), `MEDIA_TYPE_UNDECLARED` / `RESPONSE_HEADER_MISSING` WARNs, the request body is checked BEFORE sending as WARNs (`REQUEST_SCHEMA_MISMATCH`, `REQUEST_BODY_MISSING` — the request still goes out; the point is to observe). The SQL leg compares the dataset's declared columns with the live `ResultSetMetaData` through `OdcsTypes.kt` — ODCS `logicalType` → PostgreSQL type-name families (string: varchar/text/bpchar/char/name/uuid/citext/inet/cidr/macaddr/xml/interval; integer: int2/int4/int8/smallint/integer/bigint/serial/bigserial/oid; number: numeric/decimal/float4/float8/real/double precision/money; boolean: bool; date: date/timestamp/timestamptz/time/timetz; array: `_`-prefixed; object: json/jsonb/hstore) — `COLUMN_MISSING` / `COLUMN_TYPE_MISMATCH` ERROR, `COLUMN_EXTRA` / `COLUMN_NULLABLE_MISMATCH` / `REQUIRED_VALUE_NULL` WARN, `COLUMN_TYPE_UNKNOWN` INFO, paths under `/schema/{i}/properties/{j}`; the nullable rule applies to datasets declared `physicalType: table` only — PostgreSQL's catalog carries no NOT NULL for a VIEW's columns, so every view column reads as nullable and the rule would be noise there (the sample's actual NULLs still fire `REQUIRED_VALUE_NULL`); a declared relation absent from the database is `DATASET_MISSING` (ERROR). Tests: `TryCatalogTest`, `ConformanceTest` (pure), the route cases in `ContractVersionTest`.

**Inference (release 0.8.0, `contracts/infer/`).** `POST /api/v1/contracts/infer` derives a DRAFT document from real samples — computed per call, stored nowhere, exactly like try-it above; every heuristic applied rides back as a `source = INFERENCE` note beside the draft, never blocking. `SchemaInference.kt` is the one JSON → JSON Schema inferencer every builder funnels through: types merge across every sample seen at one position (integer ∪ number → `number`; a JSON `null` folds into a type ARRAY rather than dropping the property; several non-null types produce a type array plus a WARN `INFER_MIXED_TYPES`), `required` = present AND non-null in EVERY object sample, `format` (`date-time`/`date`/`time`/`uuid`/`email`/`uri`) is asserted only when EVERY non-null string at that position matches it — no `enum`, no examples, no bounds — and the walk is bounded by the reader's `RenderBudget` (32 deep / 20k nodes; past it an empty `{}` plus ONE WARN `INFER_TRUNCATED` for the whole build). **OpenAPI** (`OpenApiInference.kt`, `openapi: 3.1.0`): HTTP exchange samples are grouped into paths by `PathTemplates.kt`'s classifier — a segment becomes `{param}` when it looks like an id (an integer, a UUID, a long hex string, or an opaque ≥16-char token with a digit), named from the PRECEDING static segment singularised naively (`ies`→`y`, a trailing `s` drops unless the word ends `ss`) plus `Id` (`/orders/123` → `{orderId}`; no preceding segment → `{id}`; dupes suffixed) — one `INFER_PATH_TEMPLATED` note per templated path; there is deliberately no cross-sample VARIATION merging (`/users/alice` and `/users/bob` stay two literal paths). Operations group by (method, template); `operationId` = method + PascalCased static segments + `By<Param>` (`getOrdersByOrderId`, deduped); query parameters are `required` iff present in every grouped exchange, typed boolean/integer/number/string from the observed values; a request/response body infers a schema when its media type is JSON-like (null content type defaults to JSON), else the media type is recorded alone with `INFER_BODY_NOT_JSON`; response `description` is `HttpStatusCode.fromValue(status).description` for a status Ktor recognises, else `"Response"`; response headers are the observed names minus a fixed deny list (`content-*`, `date`, `server`, hop-by-hop headers, `access-control-*`, `set-cookie*`, `x-powered-by`, `cf-*`, `x-amz-*`, …). Security schemes are detected from header NAMES only (values never travel): a typed `Authorization` header with scheme `bearer`/`basic`/`digest` becomes `components.securitySchemes.{bearerAuth|basicAuth|digestAuth}` (`type: http`), any other scheme word becomes an `apiKey` header scheme named `Authorization`; a fixed list of api-key-shaped header names (`X-Api-Key`, `X-Auth-Token`, …) becomes a camelCased `apiKey` scheme; `cookie` is never turned into a scheme; an operation gets a `security` entry only when EVERY exchange grouped into it carried the header — one `INFER_SECURITY_DETECTED` note per scheme. **AsyncAPI** (`AsyncApiInference.kt`, `asyncapi: 3.0.0`): one channel per message batch, its id a camelCase of the topic split on `[.\-/_ ]` (`orders.v1.created` → `ordersV1Created`), its message declared INLINE inside the channel (`channels.<id>.messages.<Pascal>Message`, never `components.messages`) and one `send<Pascal>` operation per channel whose message `$ref` points INTO the channel, never `components` — the 3.0 message/payload shape accepts a type array without complaint. A payload shaped like a CloudEvents envelope (string `specversion`/`id`/`source`/`type`) lifts its `data` sub-schema out to `components.schemas.<Pascal>Data` with an `INFER_CLOUDEVENTS` note; there are no `servers` in v1. **ODCS** (`OdcsInference.kt`, `apiVersion: v3.0.2`): root fields are exactly `blankTemplate`'s (`apiVersion`, `kind: DataContract`, `id` a slug of the name, `name`, `version`, `status: draft`, `description.purpose: ""`, `schema[]`). One dataset per relation; a schema-qualified name (`public.users`) keeps only the bare relation name with an `INFER_SCHEMA_QUALIFIED` note (ODCS datasets carry no schema). From columns: `logicalType` is the reverse of the try-it SQL leg's family table (`OdcsTypes.logicalTypeOf`, `_`-prefix/`[]`-suffix → `array` with an `items.logicalType`; a type outside every family → `string` with `INFER_TYPE_UNKNOWN`), `required = !nullable`, `primaryKey`/`primaryKeyPosition` when given. A VIEW omits `required` on every property (its catalog carries no NOT NULL) with exactly ONE `INFER_VIEW_NULLABILITY` note per relation. From rows: `SchemaInference.infer` over the parsed JSON objects, then its JSON Schema properties map onto ODCS properties (a `string` with `format: date`/`date-time` becomes ODCS `date`; nested `object`/`array` map to nested `properties`/`items`). **Columns win for type and required; rows only ADD properties columns did not declare.** Not in v1 (documented limits): variation-based path merging, array query parameters, non-JSON body schemas, Avro payloads, AsyncAPI `servers`, examples/descriptions beyond the required response description, merging into an existing version's text. `DocumentWriter.kt` is the ONE place Covenant writes a document (into a response body only, never stored) — a `YAMLMapper` with `MINIMIZE_QUOTES` + `ALWAYS_QUOTE_NUMBERS_AS_STRINGS` + `INDENT_ARRAYS_WITH_INDICATOR`, no doc-start marker, and a custom `StringQuotingChecker` that additionally quotes YAML-1.1-ambiguous leading indicators (`*`/`&`/`@`/a bare `-`) and exponent-shaped numbers (`1e3`) that Jackson's own numeric-quoting feature misses — pinned by a round-trip test (`DocumentParser.parse(yaml(tree))` reproduces the tree exactly) rather than by inspection.
